# Harness Engineering（公开要点摘录 / 我的短笔记）

> 来源：OpenAI · Harness engineering — https://openai.com/index/harness-engineering/
> 说明：以下为公开思想的中文摘录与个人笔记，非原文照搬。卡设计时翻阅即可。

## 核心观点

"Harness" 指的是围绕模型搭的**执行环境与反馈回路**，而不是模型本身。让 Agent 有用，关键往往不在于换更强的模型，而在于人类把「环境、约束、工具、可验证的反馈」设计好。

- **人类的稀缺资源是注意力**。好的 harness 让人只需定义边界与目标，把重复的执行/验证交给 Agent，人只在关键点介入。
- Agent 需要能**自己判断对错**，所以必须给它**可机器验证的反馈**（测试、可量化指标、可复现脚本），而不是靠人一步步点头。
- 环境要**受限而明确**：清楚的权限边界、清楚的成功判据，能减少 Agent 跑偏或做无用功。

## 对本实验的启发

1. 反馈眼睛 = 单元测试 + 批量模拟 + 三指标（达成率 / 破产率 / 策略分化）。没有它，Agent 只能靠「看起来对」交差。
2. 边界写死在 `HARNESS.md`（可向本仓 push 功能分支并开 PR；禁 force-push、禁其他仓、禁碰真金），让 Agent 自主但不失控。
3. 目标与验收写死在 `ACCEPTANCE.md`，具体玩法/技术栈留给 Agent 决定——测的是「人定边界 + Agent 自主闭环」。
4. 判断 harness 是否成功：Agent 是**真的在用反馈改经济**，还是只在堆功能 / 刷 KPI。
